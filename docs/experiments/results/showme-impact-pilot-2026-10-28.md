# Test SHOWME against a direct-model baseline on IMPACT

**Outcome: no advantage demonstrated; selected annotated error and recovery missed by both.** October 28, 2026. This is a small diagnostic, not the official IMPACT benchmark.

## Question and isolation

Does SHOWME's learned process help identify an annotated procedure issue and subsequent recovery better than a straightforward multimodal comparison given the same example and attempt evidence?

Use official IMPACT v1.1 TAS-B front-view annotations and public videos, acquired as described in `../datasets/public-procedure-datasets-2026-10-28.md`. The model received neutral silent filenames only, not annotation JSON, phase labels, expected error descriptions or the scorecard. Clip selection used annotations, so this is a targeted diagnostic, not a randomly sampled held-out benchmark.

- Example: ER07AD15_Disassembly_A_001, source seconds 31–56.5. Both hand streams are normal in the selected interval.
- Control: separate execution ER07AD15_Disassembly_A_004, seconds 25–38, normal interval.
- Learner interval: that second execution, seconds 38–51, contains one right-hand spatial anomaly and a later annotated recovery action.

The videos show the same participant in different executions. They do not establish cross-person generalization. The example is a partial subprocedure, not a full expert demonstration. Annotation-marked normal does not guarantee it reveals every rule needed to judge later actions. In particular, the spatial tool-placement expectation is not explicitly specified in the selected example; this is an important limitation of the test.

## Methods

Muse Spark 1.3, minimal reasoning. One example extraction generated four states/three transitions. SHOWME Observe v5 compared the fixed process against control and learner clips separately. The direct baseline received the example video and each attempt, with a straightforward evidence-based mistake/correction prompt, without the distilled process. Output schemas differ, so this is not a schema-controlled ablation. Both methods were told not to assume a mistake or treat a different order as inherently wrong.

One baseline file-upload attempt stalled for over 266 seconds and was interrupted before inference. No baseline verdict was generated by it. The four comparisons then used documented inline-video inputs, explicit 75-second request timeouts, no inference retries. The five completed inferences (including learning) returned valid structured output.

## Failure analysis

The learned process identified a generic main assembly, generic hand tool, turning and small-part separation. It did not encode tool-specific contact, workspace placement requirements or a known error condition. In the learner interval SHOWME observed the tool being placed on the mat, but called the broader manipulation state consistent. Both methods cited small parts, occlusion or absent requirements as limitations.

The present process representation did not add the information needed to detect this issue. Tighter output validation alone cannot repair missing visual/source understanding. The direct baseline also failed, so this does not show the underlying model can solve the chosen case unaided. The absent explicit placement protocol limits any broader interpretation.

## Next decision

Use a source-supported, visibly distinguishable target (for example an annotated wrong-tool/part event whose correct counterpart is visible in another execution) before spending more calls on ambiguous placement rules. Hold reference, prompt, learner interval and scoring fixed for each method. If useful discrimination still fails, narrow/reconsider the proof rather than add infrastructure.
